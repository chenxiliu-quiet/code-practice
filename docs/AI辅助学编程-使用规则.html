AI 辅助学编程 · 使用规则

大连东软信息学院 · 软件工程大一 · 2026.10 制定
一句话结论：AI 不是禁品，是处方药——决定它是药还是毒的，不是"用不用"，而是剂量和时机。
唯一的分界线：关掉 AI 之后，你还能不能写出代码、调出 bug、交上作业？
想直接要答案？可以。但请满足本页第①节的三个前提——那三个前提就是把"抄答案"变成"学东西"的全部差别。

① 关于"能不能直接要答案"——可以，但要满足三个前提

看懂别人的代码本身就是一种学习（阅读优秀代码是正经方法）。真正的问题不是"看了答案"，而是答案出现得太早，以及看懂之后你没有生成过。 "我能看懂" ≠ "我能写出来"——这是两套不同的脑回路。
前提具体做法为什么
时机 先自己挣扎 20–30 分钟，并且能一句话说清"我卡在哪"——是语法不会、逻辑想不出、还是报错看不懂？ 带着具体卡点看答案，大脑是在"补洞"；一上来就要答案，大脑是在"抄写"
动作 拿到答案后关掉它，从空白重写一遍（不许复制粘贴），并在注释里写下"我原来错在哪" 生成效应：自己写一遍 > 读十遍
验证 第 3 天不看答案再写一遍 + 做一个变体（换输入 / 加条件 / 换数据结构） 间隔重复 + 迁移，这一步过了才算真的进脑子

三问检验（看完 AI 的代码后，立刻自测）

#问题做不到说明什么
1关掉它，我能在白纸 / 空白文件里重写出来吗？这次看答案只是"消费"，不是学习——请回到前提②重做
2每一行为什么这么写？换成别的写法（比如用 if 代替三元）会怎样？
3改一个需求（多输入一个数 / 加一个判断 / 换成集合）我还能写吗？

三项都能做到 → 这次"要答案"是有效学习（等价于看题解）；任何一项做不到 → 那次只是消费。三问检验也是我给答案时的默认附赠。

② "我能看懂你的代码"——看懂属于第几层？

层次能力表现算不算学会
L1读懂能看懂别人写的代码在干什么（"我能看懂"通常停在这一层）不算
L2解释能说清为什么这么写、把哪一行改掉会坏掉刚起步
L3重现关掉答案，从空白写出来，一次跑通✔ 算学会了
L4变体改需求、换结构、优化写法都能自己完成✔ 牢固
L5迁移在新问题上主动想到用这个套路✔ 真本事
注意一个骗局：读 AI 代码时，大脑在做"确认"（这条我看得懂），而独立写代码时大脑在做"构造"（从零搭出来）。 确认比构造容易得多——所以"看完觉得很简单"是假象，就像看别人打游戏和自己打。 把 L1 变成 L3，那一次看答案才真的赚到。

③ 按作业类型决定"能不能要答案"

作业类型能不能要答案怎么做
计分作业 / 学校 OJ / 期末考
老师能看提交记录、考试是手写卷		 不要整段要了再交 可以要"看懂"，但必须自己重写一遍、用自己的写法提交。整段 AI 代码提交 = 学术诚信风险 + 老师一眼看得出 + 考试立刻露馅（你作业里那个多空格判错就是例子）
自学练习
黑马课后作业、洛谷、PTA 非计分题		 随便要 重点不在"要不要"，而在"能不能讲清 + 能不能重写"。用第①节的三个前提走一遍即可
环境 / 工具 / 报错 / 配置
JDK 装不上、IDEA 报错、Git 不会用		 直接要答案 零心理负担——这不是学习内容，是噪音。把时间省下来写代码

④ 三条线：红线 / 黄线 / 绿线

线行为说明
红线① 计分作业 / OJ 直接让 AI 写完提交
② 语法期（大一上）开全自动补全写练习
③ 报错第一反应是贴给 AI，从不自己读报错		分别毁掉：诚信与真实水平、肌肉记忆、debug 能力（工程师的核心能力）
黄线① 让 AI 生成完整代码，但你能逐行讲清楚
② 大一下起用 AI 写样板代码（CRUD、配置、界面布局）		可以，但必须付出"讲清楚 + 重写一遍"的代价；讲不出来就删掉自己重写
绿线① 概念讲解器（"用大一学生的话解释多态"）
② 报错翻译器（要方向，不要答案）
③ 代码评审（"先说问题，别直接给我重写版"）
④ 出题 / 生成变体（"给我 3 道变体题，先别给答案"）
⑤ 苏格拉底提问者（"每次只问我一个问题"）
⑥ 最小可运行示例		几乎无副作用，越早用越好。这六条是你提问的推荐姿势

⑤ 按阶段：AI 该扮演什么角色

阶段AI 的角色插件设置
大一上
现在：语法 / 数组 / 方法		讲解 + 报错翻译 + 出题关掉 inline 自动补全（或改成手动 Tab 触发）；练习代码 100% 自己写
大一下
集合 / IO / 项目		code reviewer + 样板代码工人补全可开；核心逻辑自己写
大二pair programmer全面使用；架构决策自己定
大三+/工作生产力标配不用反而慢

⑥ 六条使用契约（贴在显示器边上）

① 提问必带三件套：我的代码 + 我的思路 + 完整报错。只问"这题怎么做"是最低效的用法。
② 默认要"解释"不要"代码"：明确说"先别给完整代码，给我思路"。
③ 30 分钟规则：卡住 30 分钟再问（比"立刻问"慢，比"永远不问"快）。
④ 留下来的每一行都要能解释：讲不出来 = 删掉重写。这一条能挡掉 90% 的伤害。
⑤ 每周一次"裸写日"：关 AI、关文档、关视频，从空白文件写一段完整程序。
⑥ 定期模拟无 AI 场景：期末手写卷、面试白板、实习笔试——这些场景 AI 一点忙都帮不上。

⑦ 四个提问话术模板（照抄就能用）

❌ 低效 / 有害✅ 高效 / 安全
"帮我写一下这道题。" "这道题我写到这卡住了【贴代码 + 报错】，我怀疑是 XX 问题，下一步该往哪想？先别给完整代码。"
"这段代码什么意思？"（贴一大段） "我写完了但感觉绕。先说问题，再给我一个更精简的版本，我自己重写一遍。"
"为什么我的代码报错？"（不贴报错） "第 3 行为什么要用 StringBuilder？直接 + 拼接会怎样？"
"给我一份能过的答案。" "给我完整答案，但先只给思路框架，我自己写，写完再对照。"

⑧ AI 的诚实清单（这些话它对你说不出口，我替它说）

局限对你的影响 / 对策
会自信地给出错代码（边界条件、并发、API 版本最容易翻车）任何代码都要自己跑一遍、测边界值（空值、0、最大、负数）
会给你超纲写法（Stream、正则、递归、lambda）大一阶段看不懂的写法一律要求"换成我学过的语法"；OJ 上还可能被判超时
倾向于顺着你说（你问"我这样写对吧"，它可能答"基本可以"）别问"对不对"，问"这里有哪三种可能出错的地方"
知识有截止时间，新版 API 会过时关键 API 以官方文档 / IDE 提示为准
看不到你的完整上下文（老师要求、评分标准、课程进度）提问时把要求贴给它：题目原文、老师的提交要求、你学到第几章

⑨ 每周自检（30 秒）

"如果 AI 明天全部消失一周，我还能不能写出代码、调出 bug、交上作业？"
能 → 你在用它加速；不能 → 你在用它替代自己，而这个差距会在大二（学校考试、面试白板、实习笔试）一次性暴露。

为什么这样定规矩：学习编程依赖"合意困难"（检索、试错、调试），而 AI 直接给答案会造成认知卸载，短期效率上升、长期技能留存下降。 相关讨论见：The AI Skill Development Framework: From Cognitive Offloading to Skill Retention、 SIGCSE TS 2025：Evaluating GenAI's Effectiveness for Students with Varied Programming Backgrounds、 The Silent Erosion: Vibe Coding and the Decline of Programming Literacy。
